# Protocol libraries in dcc-bigfred/proto

Copy and refine LocoNet, Z21, and WiThrottle as twin Go and Rust libraries
(client + server, Go-generated shared test vectors, OTel instrumentation).
BigFred and LongFred are not touched in this initiative — cutovers are
separate plans.

## Starting point

This repo began empty (Apache-2.0 LICENSE + README).

In **bigfred**:

- `pkgs/loco/commandstation` — **client only** of a physical command station:
  `Station` plus optional `SlotManager` / `TrackPowerController` / atomic
  metrics. Transports: serial, TCP ASCII (LbServer), TCP binary, UDP Z21.
- `dcc-bus/z21server` (UDP :21105, **duplicated** codec vs `z21_proto.go`) and
  `dcc-bus/withrottle` (TCP :12090) — inbound handset servers, tangled with
  Redis pairing, roster, and `remotes.InboundDrivePort`.
- OTel: dcc-bus maps snapshots onto observables (`StartZ21Metrics` / LocoNet
  equivalent).

In **longfred**: `crates/proto` — own WiThrottle/Z21 adapters, `#![no_std]`,
no `alloc` (`heapless`), no sockets.

## Scope

**This plan changes only the `proto` repo.** BigFred, the docs site, and
LongFred stay as they are; dual maintenance is accepted until cutover.

In proto: codecs, client sessions, server listeners, LocoNet gateway, OTel
instrument registration, protocol specs, test vectors.

Out: pairing, Coordinator, roster policy, `InboundDrivePort`, OTLP exporter, UI.

LocoNet server in this plan = **gateway** (forward frames, no slot table). A
virtual station (LOCO_ADR/SPD/DIRF → `DriveHost`) is a later plan.

## API

### Go client (`Station`)

Copy signatures from bigfred `interface.go`: `SetSpeed` / `GetSpeed` /
`SendFn` / `ListFunctions` / `ReadCV` / `WriteCV` / `CleanUp` plus optional
`SlotManager`, `TrackPowerController`, `MetricsSource`, same sentinels
(`ErrSlotInUse`, `ErrLncvAppliedNoAck`, …). Constructors `NewZ21Roco`,
`NewLocoNetSerial`, `NewLocoNetTCP`, `NewLocoNetTCPBinary` unchanged so a
later cutover is mechanical.

**New: `commandstation.NewWiThrottle(host, port) Station`** — BigFred will also
reach a command station over WiThrottle (JMRI, DCC-EX, LNWI, RB1110).
Speed/dir/fn via `M0A` / `M0V` / `M0R` / `M0F`, `SetTrackPower` via `PPA`,
heartbeat `*`. WiThrottle has no CV programming → `ReadCV` / `WriteCV` return
`ErrUnsupported` (new sentinel next to `ErrTrackPowerUnsupported`). Roster
`RL` is an optional interface, not `Station`. LAN scan:
`WiThrottleAutodetection` (TCP :12090, URI `withrottle://host:port`).

### Go server (`DriveHost`)

One contract for Z21 and WiThrottle; this is what BigFred later adapts to
`InboundDrivePort`:

```go
type LocoState struct {
    Addr      uint16
    Speed     uint8
    Forward   bool
    Steps     uint8
    Functions uint32 // bitmask F0..F31
}

type DriveHost interface {
    SetSpeed(client ClientID, addr uint16, speed uint8, forward bool, steps uint8) error
    SetFunction(client ClientID, addr uint16, fn uint8, on bool) error
    LocoState(addr uint16) (LocoState, error) // GET_LOCO_INFO / M0A
    SetTrackPower(client ClientID, on bool) error
    Release(client ClientID, addr uint16)       // MT- / LAN_LOGOFF
}

// server → handsets (loco changed from another source):
func (s *Server) NotifyLocoState(st LocoState)
func (s *Server) NotifyTrackPower(on bool)
```

`ClientID` = UDP address / TCP conn + HU. Pairing via CV3/CV4 or F-keys stays
in BigFred as a `DriveHost` wrapper — the library does not need POM hooks.

- `z21.Listen(bind, host) (*Server, error)` — default :21105; handshake
  (`LAN_GET_SERIAL_NUMBER`, HW info, broadcast flags), `LAN_X_SET_DRIVE` /
  `SET_FUNCTION` / `GET_LOCO_INFO` / track power, `LOCO_INFO` fanout.
- `withrottle.Listen(bind, host) (*Server, error)` — default :12090; `VN` /
  `HT` / `HU` / `PW`, MultiThrottle `M`, heartbeat `*`, `PPA`, roster via
  optional `RosterProvider`.

Copy from `z21server` / `withrottle`: framing, handshake, packet builders,
dispatcher I/O, `wire_state`. Do not copy: `pairing*.go`, `sentinel.go`,
`roster.go` tied to `contract`, `NewGateway`.

### Go LocoNet gateway

One model: **one upstream** (`loconet.Upstream`: serial or TCP client,
obtained from `commandstation.OpenLocoNet*` — see P6.3), **N downstream**
listeners; every packet from any end is broadcast to the others.

```go
up, _ := commandstation.OpenLocoNetSerial("/dev/ttyUSB0", 57600)
gw := loconet.NewGateway(up)
gw.Listen(":1234", loconet.Binary)  // raw bytes (RocRail lbtcp)
gw.Listen(":5550", loconet.ASCII)   // LbServer SEND/RECEIVE
```

Loopback tests: existing `NewLocoNetTCPBinary` / `NewLocoNetTCP` as gateway
clients.

### Rust

**`z21` + `withrottle` clients — hard requirement for LongFred:** `#![no_std]`,
**no `alloc`**, no sockets. Shape like current `WtAdapter` / `Z21Adapter`:
`on_connect(out)`, `on_bytes(in, emit)`, `encode(cmd, out)` on `heapless`
buffers. TCP/UDP stay in firmware (`embassy-net`). This plan designs the API
for a later LongFred swap; it does not perform that swap.

**No consumer today → dummy:** `z21-server`, `withrottle-server`, `loconet`,
`commandstation` (`std`). Public API aligned with Go (same operations),
minimal implementation: compiles, later passes codec goldens, servers do
handshake + `SetSpeed`/`SetFunction` into `DriveHost` (enough for interop),
the rest `todo!()` with `#[doc = "experimental"]`. No OTel, no serial.
Grown only when a consumer appears.

## Telemetry

Hot path unchanged: lock-free atomics, zero allocation, no OTel per frame.
`MetricsSnapshot` / `Z21MetricsSnapshot` remain.

Package **`go/telemetry`** (only importer of `go.opentelemetry.io/otel` +
`otel/metric`, **not** the SDK): `RegisterLocoNet(meter, src, attrs)`,
`RegisterZ21(...)`, `RegisterWithrottle(...)` attach observable callbacks to
the snapshot (logic copied from dcc-bus `metrics_*.go`). Without a

## Go ↔ Rust equivalence

Goal: the same bytes and drive/fn/CV semantics on the wire, not identical type
names. Libraries do not link in production; firmware and the client crate
contain no FFI or CGO.

**Layer 1 — vectors generated by Go.** `go run ./cmd/gen-vectors` (seeded,
deterministic; hand-picked edge cases plus property-style volume) writes
`testdata/{proto}/*.json`:

```json
{ "cases": [ { "id": "...", "hex": "...", "op": "loco_info", "fields": { "addr": 10, "speed": 50, "forward": true, "steps": 128 } } ] }
```

Binary protocols use `hex`; text protocols (WiThrottle) use `line` instead
(`"line": "M0AS3<;>f10"`). Exactly one of `hex` or `line` per case.

Directions: `hex|line → fields` (decode) and `fields → hex|line` (encode when the layout
is canonical). Go tests its codec against the same files; Rust has ordinary
`#[test]` reading `testdata/` (host, `no_std` crate). CI: `go-test`,
`rust-test`, `rust-nostd` (client crates built for a bare-metal target, see
P6), `vectors-fresh` (`gen-vectors` then `git diff --exit-code`). No Go
toolchain inside `cargo test --workspace --exclude dcc-proto-interop`.

**Layer 2 — network interop (`rust/interop/`, Linux).** Rust no_std client +
`std::net` in the test ↔ Go `z21.Listen` / `withrottle.Listen` with a
`DriveHost` recorder. Scenario: handshake → `SET_DRIVE addr=3 speed=50` →
recorder `SetSpeed(3,50,true,128)` → `SET_FUNCTION F0` → `SetFunction`;
WiThrottle analogously `N`/`HU`, `M0A`, `M0V`. Also same-language: Go
`NewZ21Roco` ↔ Go `z21.Listen`, Go `NewWiThrottle` ↔ Go
`withrottle.Listen`, Go LocoNet clients ↔ Go gateway. Rust dummy servers join
the matrix only to the extent they implement.

Not compared: pairing, BigFred roster, OTLP, LocoNet TX pacer timing (Go unit
tests), ESP/embassy.

## P6 — review fixes (design)

Order matters: P6.0–P6.2 unblock a real handset; P6.3 unblocks the
BigFred gateway story; P6.4 unblocks LongFred; the rest is parity and hygiene.

### P6.0 — WiThrottle server: `F` is press/release, `f` is force

Today `handleAction` maps `F1n` → on and `F0n` → off. Engine Driver sends
`F1n` on button-down and `F0n` on button-up for every function, so a
latching F0 (headlight) goes on and immediately off. Spec §9.3–9.5: `F` is
press/release, `f` is absolute, `m` overrides momentary/latching. The
`Station` client already sends `f` and is not affected.

**State.** Per session, per loco, the server needs to know which functions
are momentary. Default: all latching except **F2** (JMRI default, horn).
The consumer may know better from its roster, so `DriveHost` gets an
optional interface — same pattern as `SlotManager` on `Station`:

```go
// drive — optional; when the host does not implement it, the server uses
// the package default (F2 momentary, everything else latching).
type FunctionModer interface {
    Momentary(addr uint16, fn uint8) bool
}
```

```go
type session struct {
    …
    momentary map[uint16]map[uint8]bool // addr → fn → override from `m`
}
```

**Dispatch** in `handleAction`, replacing the shared `F`/`f` case:

```go
case prop[0] == 'f': // force: absolute
    fn, on, ok := parseForce(prop)
    for _, addr := range addrs { s.setFn(sess, addr, fn, on) }

case prop[0] == 'F': // press / release
    fn, pressed, ok := parsePress(prop)
    for _, addr := range addrs {
        switch {
        case s.isMomentary(sess, addr, fn):
            s.setFn(sess, addr, fn, pressed)   // down = on, up = off
        case pressed:
            cur := s.fnState(addr, fn)          // host.LocoState().Functions
            s.setFn(sess, addr, fn, !cur)       // latching: toggle on press
        default:
            // latching release: no-op
        }
    }

case prop[0] == 'm': // m1n momentary / m0n latching, per session+loco
    fn, mom, ok := parseMode(prop)
    for _, addr := range addrs { sess.setMomentary(addr, fn, mom) }
```

`isMomentary` order: session `m` override → `host.(FunctionModer)` →
package default. `fnState` reads `host.LocoState(addr).Functions`; if the
host errors, fall back to a session-local bitmask so a toggle still
alternates.

**Echo.** After a successful `SetFunction` the server writes
`M<t>A<key><;>F<state><n>` back to that session only when the bit
actually changed (§9.4). Other sessions get it through the consumer's
`NotifyLocoState`, as today.

**Codec.** `parseFunctionAction(prop) (fn, on, force, ok)` splits into
`parsePress` / `parseForce` / `parseMode` in `line.go`; the `force` flag
disappears. `ParseM` is unchanged.

**Tests** (`server_test.go`, recorder host):

- Spec B.1 pair `F11` → `F01` on a latching F1: exactly one
  `SetFunction(3,1,true)`; the second pair gives `SetFunction(3,1,false)`.
- `F12` → `F02` with default modes: `SetFunction(3,2,true)` then
  `SetFunction(3,2,false)`.
- `m01` then `F11`/`F01`: F1 becomes momentary, two calls; `m12` then
  `F12`/`F02`: F2 latching, one call.
- `f11` twice: one `SetFunction`, one echo line (no echo on no-change).
- Host implementing `FunctionModer` returning `true` for F3 overrides the
  default; a session `m03` overrides the host.
- Testdata: `testdata/withrottle/function_press.json` with the same lines,
  so the Rust `withrottle-server` dummy can adopt the semantics later.

### P6.1 — servers never write while holding `mu`

Both servers take `s.mu` and then write to the socket inside `Notify*`. The
read/accept path takes the same lock, so one stalled peer freezes every
handset.

Z21 (`go/z21/server.go`): snapshot targets under the lock, write outside.

```go
func (s *Server) NotifyLocoState(st drive.LocoState) {
    pkt := BuildLocoInfo(st)
    s.mu.Lock()
    targets := make([]*net.UDPAddr, 0, len(s.peers))
    for key, p := range s.peers {
        if p.wants(st.Addr) { targets = append(targets, p.addr) }
    }
    s.mu.Unlock()
    for _, ua := range targets { _, _ = s.conn.WriteToUDP(pkt, ua) }
}
```

WiThrottle (`go/withrottle/server.go`): every write goes through the
session, never through `writeLine(sess.conn, …)` directly.

```go
type session struct {
    conn net.Conn
    wmu  sync.Mutex // serializes writes; never held together with Server.mu
    …
}

const writeTimeout = 5 * time.Second

func (sess *session) write(line string) {
    sess.wmu.Lock()
    defer sess.wmu.Unlock()
    _ = sess.conn.SetWriteDeadline(time.Now().Add(writeTimeout))
    if _, err := sess.conn.Write([]byte(line + "\n")); err != nil {
        _ = sess.conn.Close() // serve() returns, drop() releases locos
    }
}
```

`NotifyLocoState` / `NotifyTrackPower`: collect `[]*session` (and the
per-session throttle id) under `s.mu`, unlock, then `sess.write`. Same
change in `handleM` / `sendBurst`. Test: a peer that never reads (TCP window
full) must not block `NotifyLocoState` for a second, well-behaved peer.

### P6.2 — Z21 server: function groups, broadcast flags, peer lifetime

**Function groups.** `go/z21/parse.go` gets

```go
// ParseSetLocoFunctionGroup is LAN_X_SET_LOCO_FUNCTION_GROUP (0xE4, DB0 0x20…0x29).
// Returns the F-range of the group and the new bits, LSB = lowest function.
func ParseSetLocoFunctionGroup(pkt []byte) (addr uint16, lo, hi uint8, bits uint32, ok bool)
```

Group → range: `0x20` F0–F4 (F0 is bit 4, F1–F4 bits 0–3), `0x21` F5–F8,
`0x22` F9–F12, `0x23` F13–F20, `0x28` F21–F28, `0x29` F29–F31. Server
handling: read `LocoState(addr).Functions`, diff bits `lo..hi`, call
`SetFunction` once per changed function, then `echoLoco`. `DriveHost` does
not change. `gen-vectors` gets one case per group under
`testdata/z21/function_group.json`; Rust `parse` only (LongFred sends single
`0xF8`), encode optional.

**Broadcast flags.** Replace `peers map[string]*net.UDPAddr` +
`subs map[string]map[uint16]struct{}` with one record:

```go
type peer struct {
    addr     *net.UDPAddr
    flags    uint32              // LAN_SET_BROADCASTFLAGS, default 0
    subs     map[uint16]struct{} // GET_LOCO_INFO addresses
    lastSeen time.Time
    held     map[uint16]struct{} // addresses this peer drove (SET_DRIVE / SET_FUNCTION)
}
```

- `LAN_SET_BROADCASTFLAGS` (0x50) stores `flags`; `LAN_GET_BROADCASTFLAGS`
  (0x51) returns them instead of zeros.
- `NotifyLocoState`: peer gets it when `flags&0x00010000 != 0` (all locos),
  or `flags&0x00000001 != 0 && subs[addr]`. Peers with `flags == 0` get
  nothing, per spec.
- `NotifyTrackPower`: peers with `flags&0x00000001 != 0`.

**Peer lifetime.** Spec: a client that is silent for 60 s is forgotten.
`lastSeen` updated in `notePeer`; a ticker (every 10 s) evicts peers older
than `peerTTL = 60 * time.Second` and calls `Release(id, addr)` for each
`held` address. `LAN_LOGOFF` does the same eviction. This removes
`Release(client, 0)`; `addr` in `Release` always means one loco, same as the
WiThrottle server today.

`Listen(bind, host)` signature stays; TTL is a package constant.

### P6.3 — LocoNet: exported transports, one framing, safe Close

**Transports.** `loconet.Upstream` stays as is. `go/commandstation` exports
the raw transports so a `Gateway` can own the physical port:

```go
// commandstation
type LocoNetTransport interface {
    WritePacket(pkt []byte) error
    Recv() <-chan []byte
    Close() error
}

func OpenLocoNetSerial(device string, baudrate int) (LocoNetTransport, error)
func OpenLocoNetTCP(host string, port uint16) (LocoNetTransport, error)       // LbServer ASCII
func OpenLocoNetTCPBinary(host string, port uint16) (LocoNetTransport, error)
```

Implementation: `rxCh := make(chan lnPacket, 64)`, call the existing
`newLn*Transport(…, rxCh)`, and a goroutine that copies `lnPacket` →
`[]byte` onto the public channel until `Close`. `loconet.Upstream` is
satisfied structurally: `loconet.NewGateway(commandstation.OpenLocoNetSerial(...))`.
The existing `NewLocoNetSerial` etc. keep their private path untouched.

A `LocoNet` station and a gateway cannot share one serial port; the
documented pattern is `gw.Listen(":1234", loconet.Binary)` and
`NewLocoNetTCPBinary("127.0.0.1", 1234)` for the local station. Test:
serial not available in CI → `OpenLocoNetTCPBinary` against a second
`Gateway` acting as the “physical” end.

**One framing.** `lnChecksumOK`, `lnMsgLen`, `lnStreamParser` move out of
`commandstation/loconet_proto.go`; `commandstation` imports `go/loconet`
and uses `loconet.ChecksumOK` / `MsgLen` / `StreamParser` (same shape as the
Z21 codec extraction in P2). `go/loconet` must not import `commandstation`;
`gateway_test.go` becomes `package loconet_test` to avoid the cycle.

**Close.** `Recorder.Close` is idempotent (`sync.Once`); `Gateway.Close`
returns `nil` on the second call instead of re-closing the upstream.

### P6.4 — Rust: bare-metal CI, no swallowed encode errors

**CI job `rust-nostd`** in `.github/workflows/ci.yml`:

```yaml
rust-nostd:
  name: Rust no_std
  runs-on: ubuntu-latest
  defaults: { run: { working-directory: rust } }
  steps:
    - uses: actions/checkout@v4
    - uses: dtolnay/rust-toolchain@stable
      with:
        targets: thumbv7em-none-eabihf, riscv32imac-unknown-none-elf
    - run: cargo build -p dcc-proto-z21 -p dcc-proto-withrottle --target thumbv7em-none-eabihf
    - run: cargo build -p dcc-proto-z21 -p dcc-proto-withrottle --target riscv32imac-unknown-none-elf
```

Two targets on purpose: RISC-V is the LongFred class of MCU, Thumb catches
anything accidentally 32-bit-x86-ish. This replaces the “client without
`std` feature” wording — the crates have no `std` feature and do not need
one; `#![cfg_attr(not(test), no_std)]` plus a bare target is the check.

**Encode errors.** In `rust/z21` and `rust/withrottle`:

```rust
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum Error { BufferFull }

pub fn on_connect(&mut self, out: &mut WireBuf) -> Result<(), Error>
pub fn encode(&self, cmd: &Command, out: &mut WireBuf) -> Result<(), Error>
```

Every `encode_*` returns `Result<(), Error>` (today `Result<(), ()>`), and
`on_connect` propagates with `?` instead of `let _ =`. `WireBuf` capacity
gets a `const _: () = assert!(WIRE_BUF_LEN >= SERIAL_LEN + BCFLAGS_LEN);`
so the handshake can never fail at runtime anyway. No consumer yet, so the
signature change is free.

**Golden parser.** Replace the hand-written `"key": "` scanner in
`rust/*/tests` with `serde` + `serde_json` under `[dev-dependencies]` only
(the library stays dependency-free apart from `heapless`). A `Vectors`
struct mirrors the JSON schema in “Layer 1”.

### P6.5 — WiThrottle `Station` client hardening

`go/withrottle/client.go`:

- **Acquire.** `ensure` waits on a per-address `chan struct{}` that `apply`
  closes when it sees the server's `M0+<key><;>` acquire reply (or the first
  `M0A<key>` state line). After `acquireTimeout = 2 * time.Second` it
  returns `ErrAcquireTimeout` (new sentinel in `withrottle`) and does **not**
  mark the loco acquired. `HMSteal…` / `M0S` reply → `commandstation.ErrSlotInUse`.
- **Device id.** `NewClient(host, port, opts ...Option)` with
  `WithDeviceID(string)` and `WithName(string)`; default id
  `"proto-" + 8 hex from crypto/rand`, default name `"proto"`. Two clients
  from one process no longer share `HUproto`.
- **Heartbeat.** Parse `*<n>` from the burst; ticker at `n/2` seconds sends
  `*`; on write error the client is dead (`errCh`). Today the client sends
  `*+` once and JMRI will drop it after `n` seconds of silence.

### P6.6 — WiThrottle server input bounds and heartbeat

`go/withrottle/server.go`:

- `bufio.Scanner` with `sc.Buffer(make([]byte, 0, 512), maxLineBytes)`
  replaces `ReadString('\n')`; `bufio.ErrTooLong` closes the session.
- Heartbeat: session records `lastRx`. A client that sent `*+` and is then
  silent for `2 * heartbeatSecs` gets `SetSpeed(addr, 0, …)` on every held
  loco, then `Release`, then close — JMRI behaviour. `*-` disables the check
  for that session.

### P6.7 — Telemetry parity: `RegisterWithrottle`

`withrottle.Client` exposes `Metrics() Snapshot` from atomics
(`LinesTx`, `LinesRx`, `AcquireTimeouts`, `HeartbeatsSent`, `LastRxUnixNano`).
`telemetry.RegisterWithrottle(src withrottle.MetricsSource, cfg Config)`
registers `proto.withrottle.lines.tx`, `.lines.rx`, `.acquire.timeouts`,
`.heartbeats`, `.last_rx_age` (observable gauge from `LastRxUnixNano`).
Same `Config` and attribute handling as `RegisterZ21`. This makes the
ARCHITECTURE.md sentence true instead of deleting it.

### P6.8 — Interop and build hygiene

- `go/cmd/loopback-host` prints one line per recorder event
  (`SetSpeed 3 50 true 128`, `SetFunction 3 0 true`) and exits on
  `--expect N` events; the Rust tests assert the exact sequence. Scenario
  extended with `SET_FUNCTION F0` on Z21 and, on WiThrottle, the press
  pair `M0AS3<;>F10` + `M0AS3<;>F00` expecting exactly one
  `SetFunction 3 0 true` (P6.0 semantics).
- CI builds the host once (`go build -o ../rust/target/loopback-host
  ./cmd/loopback-host`) and passes `PROTO_LOOPBACK_HOST`; the test falls
  back to `go run` only when the variable is unset.
- `Makefile`: `test-rust` runs `cargo test --workspace --exclude
